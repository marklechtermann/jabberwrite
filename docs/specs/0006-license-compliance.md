# 0006: License compliance in the settings window

## Goal

Every release lists the open source components it contains, with their licenses, inside the app. Users and auditors can see what is shipped without leaving Jabberwrite.

## Scope

- New "Licenses" topic in the settings window (between Updates and About): one collapsible entry per component with name, version, SPDX license, project link and the full license text(s).
- The list is generated by `scripts/generate-licenses.mjs` (`npm run licenses`) into the single file `ACKNOWLEDGEMENTS.md` in the repository root and committed; one section per distinct license text, listing all components it applies to. The settings window embeds this file. Sources:
  - Cargo: all crates reachable from the app through normal dependencies (`cargo metadata`), license files read from the crate sources.
  - npm: production packages from `package-lock.json`, license files read from `node_modules`.
  - Native components outside both lockfiles (ONNX Runtime and the other libraries statically linked by sherpa-onnx, speech model) in a manual list inside the script, with license texts in `third-party/`.
  - Crates that ship no license file get the standard text of one of their licenses (templates in `third-party/template-*.txt`), with the copyright holders from the package metadata.
- The script checks every license against an allow-list of permissive licenses compatible with Apache-2.0 (plus file-level MPL-2.0) and fails on anything else (GPL, LGPL-only, unknown). It also fails when a component has no license text.
- The installers show and include the Apache-2.0 license of Jabberwrite (`bundle.licenseFile` in `tauri.conf.json`).
- The speech model licenses (CC BY-SA 4.0, CC BY 4.0) are listed with their full legal text. when the topic is opened, so it does not slow down the other topics.
- CI (Linux job) fails when `ACKNOWLEDGEMENTS.md` is out of date.
- `AGENTS.md` requires agents to run `npm run licenses` whenever they add, remove or update a dependency, and to add manual entries for components outside the lockfiles.

## Out of scope

Policy checks beyond the allow-list, a separate `THIRD_PARTY_LICENSES` file in the installers.
